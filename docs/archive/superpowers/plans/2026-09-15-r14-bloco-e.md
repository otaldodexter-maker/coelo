# R14 Bloco E Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** fechar os aceites executáveis do Bloco E para Conta, Chat, mídia de publicações e contratos H, mantendo R2 privado, autorização server-side e provas separadas.

**Architecture:** evoluir os contratos R2/RPC/Edge já presentes, sem duplicar catálogos ou criar um caminho de cliente-only. Cada domínio mantém seu adapter, mas o Postgres continua autoridade de tenant, owner, binding, audiência e auditoria. A rota real do Superadmin é usada para FE/E2E; migrations e Edge ficam versionadas e apenas preparadas até autorização nominal para produção.

**Tech Stack:** Flutter/Dart, `package:test`/`flutter_test`, Supabase/Postgres/pgTAP, Supabase Edge Functions/Deno, Cloudflare R2/Stream, CDP 9417 e servidor `127.0.0.1:3017`.

## Global Constraints

- Base de trabalho: `a85ac01c45dac2a615dab3fcffd64eaedcb9ff02`; `origin/dev` local diverge em `ee179b1e1474eef594a131b95f762df0dc41d647`.
- Produção Supabase/Cloudflare é somente leitura até autorização nominal; não executar `db push`, deploy, configuração de segredo/bucket ou mutação remota.
- Nenhum segredo, token, CPF, dado de criança, URL assinada ou bytes pessoais entra em Git, bundle, captura ou log.
- R2 é privado e o master nasce no R2; o Postgres guarda catálogo, ownership, binding, autorização e auditoria.
- `asset_id` é opaco e não autoriza por si; toda leitura e escrita revalida sessão, tenant, owner, entidade, finalidade e audiência.
- Fora do escopo: Planos comerciais, reader de Planos, `plans.assign`, `auth.recover/auth.reset`, recovery allowlist, `owner.r12-18`/`owner.r12-33` sem contrato/autorização, `apps/admin`, `apps/principal` e `apps/site` independentes.
- Cada fatia termina com teste focado, `git diff --check`, commit com `git add` explícito e registro em `R14-handoff-sessao-4.md`.
