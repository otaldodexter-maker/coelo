### 3.1 Drift de ACL do espelho — causa observada e correção

Primeira restauração (sem correção): `attendance_call_history_v1_test.sql` **43/44** — `not ok 4 - anon and
service_role cannot execute the wrapper`. Leitura no espelho:

```

postgres | public | f | {postgres=X/postgres,anon=X/postgres,authenticated=X/postgres,service_role=X/postgres}
anon_exec_public_fns | 519   (de 519 funções em public)
```

No dump de produção, o default de funções em `public` é só `ALTER DEFAULT PRIVILEGES FOR ROLE "postgres" IN
SCHEMA "public" GRANT ALL ON FUNCTIONS TO "postgres"` (mais `REVOKE ALL ON FUNCTIONS FROM PUBLIC` global) e
não existe nenhum `GRANT … ON FUNCTION … TO "anon"` (0 ocorrências; 516 `TO "authenticated"`, 316 `TO
"service_role"`). Como `ALTER DEFAULT PRIVILEGES … GRANT` é aditivo, o default local da imagem do Supabase
(`anon/authenticated/service_role=X`) permanece e toda função criada pela restauração nasce executável por
`anon`/`service_role`; o `REVOKE … FROM PUBLIC` do dump não alcança esses grants explícitos. É o mesmo
drift que a Sessão 8 registrou ("`anon` recebe execute por `ALTER DEFAULT PRIVILEGES` local").

Correção aplicada (espelho recriado): `supabase db reset --workdir .` → `alter default privileges for role
postgres in schema public revoke all on functions from anon, authenticated, service_role;` (defacl passa a
`{postgres=X/postgres}`) → restauração do mesmo dump (0 erros) → verificação:

